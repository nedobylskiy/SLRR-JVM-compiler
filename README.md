# SLRR-JVM-compiler

A native Node.js compiler for the Java-like **source files** used by Street Legal Racing: Redline. It reads `.java` and writes the game's TUFA `.class` format. It does not invoke Java, javac, Python, or a JVM, and it does not compile standard JVM bytecode.

The implementation follows the format and behavior documented by [TrentonCh's `slrrc`](https://github.com/TrentonCh/slrr-reverse/tree/dev/tools/slrrc). The compiler, parser, TUFA writer, and class declaration reader here are written in TypeScript. The reference project is MIT licensed.

## Install and build

Requires Node.js 20 or newer.

```sh
npm install
npm run build
npm test
```

## Compile sources

Write compiled files to a separate directory while using an installed game as the class declaration provider:

```sh
node dist/src/cli.js --root "C:/path/to/Street Legal Racing Redline" --out "C:/temp/slrr-classes"
```

Compile one source, preserving its path relative to the game root:

```sh
node dist/src/cli.js --root "C:/path/to/Street Legal Racing Redline" --out "C:/temp/slrr-classes" "C:/path/to/Street Legal Racing Redline/sl/Scripts/game/src/MainMenu.java"
```

Check parsing and code generation without writing output:

```sh
node dist/src/cli.js --root "C:/path/to/Street Legal Racing Redline" --check
```

Compare generated bytes with existing `.class` files next to each source's `src` directory:

```sh
node dist/src/cli.js --root "C:/path/to/Street Legal Racing Redline" --compare "C:/path/to/Street Legal Racing Redline/sl/Scripts/game/src/MainMenu.java"
```

Use `--float A|B|C|D` to select one of the observed float literal conversion modes; mode B is the default for Build 940. `--build N` sets the TUFA build number. The CLI refuses an output directory inside the game root.

## API

```ts
import { readFile, writeFile } from 'node:fs/promises';
import { ClassIndex, compileSource } from 'slrr-jvm-compiler';

const gameRoot = 'C:/path/to/Street Legal Racing Redline';
const index = new ClassIndex();
await index.addDirectory(gameRoot);

const source = await readFile('MyPart.java');
const result = compileSource(source, {
  ...index.compileOptions(),
  floatMode: 'B',
  // Supply a resolver if symbolic resource IDs need exact pack mapping.
  resolveResource: (pack, id) => ({ pack: pack.replaceAll('.', '/') + '.rpk', id }),
});

if (!result.ok) throw new Error(result.diagnostics.join('\n'));
await writeFile('MyPart.class', result.bytes);
```

`ClassIndex` reads TUFA declarations from `.class` files to resolve imported types, inherited fields, and methods. Its callbacks can be replaced individually with a mod loader's own lookup rules. `compileSource` accepts a string or byte buffer and returns compiled bytes plus diagnostics and class names.

## Current compatibility

The parser and emitter compile all 3,454 `.java` files in one installed Build 940 game tree, plus all 44 sources in a separate M20B25 mod. All these outputs pass strict parsing by [SLRR-JVM-decompiler](https://github.com/nedobylskiy/SLRR-JVM-decompiler). For 2,819 stock source files with an adjacent shipped `.class`, the current structural audit finds matching declarations for all 2,819, matching TREE operations and operands for 2,546, and byte-identical files for 1,919. These results describe this specific installed game and are not a guarantee that every generated script executes identically in the game.

Manual runtime check in the original Build 940 VM: `MainMenu.java` was compiled with a distinct version label, its original `.java` and `.class` were hidden, and the generated `MainMenu.class` was installed. The new label appeared in game and the menu functions were exercised without an observed failure. This multi-class file is not byte-identical to the shipped one, so this check confirms that at least some binary and TREE differences do not prevent execution. It does not validate other generated classes.

Known gaps: resource IDs that refer to external RPK packs require a `resolveResource` callback for exact mapping; some overloads and member references remain unresolved; a few control-flow patterns differ; and float literal conversion varies across shipped classes. The CLI reports syntactic or generation failures, but a successful compile does not perform game-runtime validation. Keep original files and write generated classes to a separate output directory while testing.
